RoPE 旋转位置编码
从诞生到百万长上下文的完整演进

RoPE（Rotary Position Embedding）是当今几乎所有主流大语言模型的标准位置编码方案。 本文将从数学原理出发，完整梳理 RoPE 从 2021 年诞生到 2026 年支持百万 Token 上下文的技术演进脉络， 深入解析每种扩展方法的核心思想与工程实践。

📅 2026.08 📚 LLM · Position Encoding ⚡ 阅读约 25 分钟

01 为什么需要位置编码

Transformer 的自注意力机制本质上是置换不变（permutation-invariant）的—— 打乱输入序列的词序，注意力分数矩阵的数值关系保持不变。这意味着在没有位置信息时， "猫追老鼠"和"老鼠追猫"对模型来说完全等价。 位置编码的根本使命就是向模型注入"谁在哪个位置"以及"token 之间相距多远"的信息。

图 1：自注意力的置换不变性问题
没有 Position Encoding 的 Transformer 无法区分词序——这正是位置编码要解决的核心问题。

02 RoPE 之前的方案演进

在 RoPE 诞生之前，位置编码经历了四代演进，每一代都在试图解决前一代的核心缺陷：

🕘

Sinusoidal PE 2017

用 sin/cos 函数生成固定位置向量，加到 Token Embedding 上。无需训练参数，但无法显式建模相对距离，加法操作可能污染语义信息。

无参数无相对位置
📝

Learnable PE 2018

为每个位置学习一个独立向量（BERT/GPT-2 采用）。灵活但训练长度即上限，推理时超出训练长度就完全崩溃，无法外推。

灵活无法外推
🔄

Relative PE 2019

Transformer-XL/T5 引入相对距离偏置，直接在注意力分数上加可学习偏置。关注"相距多远"而非"第几位"，但需修改 Attention 结构且参数较多。

相对位置结构复杂
📏

ALiBi 2021

在注意力分数上加线性距离惩罚（距离越远惩罚越大）。简单有效，BLOOM 采用。但数学形式固定，对超长上下文效果下降。

简单长上下文差
⚠️ 共同痛点

这些方案要么无法外推到训练长度之外，要么无法自然编码相对位置，要么需要额外的可学习参数或结构修改。能否有一种方案同时满足：相对位置 + 零参数 + 不改结构 + 可外推？

03 RoPE 的诞生（2021）

RoPE（Rotary Position Embedding） 由苏剑林等人于 2021 年在论文 RoFormer: Enhanced Transformer with Rotary Position Embedding 中提出。 它的核心思想彻底改变了位置编码的范式： 不把位置加到 embedding 上，而是旋转 Query 和 Key 向量。

🔑 设计目标

两个 Token 的注意力分数，只应依赖它们的相对距离，而非绝对位置。形式化地：

目标：内积只依赖相对位置差 m - n $$ \langle f(\mathbf{q}, m),\; f(\mathbf{k}, n) \rangle = g(\mathbf{q}, \mathbf{k}, m - n) $$

即无论 token A 在位置 5、token B 在位置 8，还是 A 在位置 500、B 在位置 503， 只要它们的相对距离是 3，注意力分数就应该相同。

图 2：RoPE 的核心直觉——旋转即编码
每个 token 的向量根据其位置被旋转不同角度。两个 token 之间的"相对角度差"天然编码了它们的距离。

04 核心数学原理

旋转操作

将 $d$ 维向量按维度两两分组，视为 $d/2$ 个复数。对第 $i$ 组二维向量 $(x_{2i}, x_{2i+1})$，在位置 $m$ 处施加旋转角度 $m \cdot \theta_i$：

二维旋转矩阵（第 i 组维度，位置 m） $$ \begin{pmatrix} x'_{2i} \\ x'_{2i+1} \end{pmatrix} = \begin{pmatrix} \cos(m\theta_i) & -\sin(m\theta_i) \\ \sin(m\theta_i) & \cos(m\theta_i) \end{pmatrix} \begin{pmatrix} x_{2i} \\ x_{2i+1} \end{pmatrix} $$

其中每组对应的频率为：

频率公式（几何级数） $$ \theta_i = \text{base}^{-2i/d}, \quad \text{base} = 10000 \text{（原始默认值）} $$

关键性质：相对位置自动涌现

对位置 $m$ 的 Query $\mathbf{q}$ 和位置 $n$ 的 Key $\mathbf{k}$ 分别旋转后，计算内积：

旋转矩阵的正交性使得绝对位置消失 $$ \langle R_m \mathbf{q},\; R_n \mathbf{k} \rangle = \mathbf{q}^T R_m^T R_n \mathbf{k} = \mathbf{q}^T R_{n-m} \mathbf{k} $$
✅ 核心结论

因为旋转矩阵满足 $R_m^T R_n = R_{n-m}$，所以注意力分数自动只依赖于相对位置 $m-n$，无需任何额外的可学习参数！这就是 RoPE 的数学之美。

代码实现

Python
import torch, math

def apply_rope(q, k, positions, head_dim, base=10000):
    """对 Query 和 Key 应用 RoPE 旋转位置编码"""
    # 计算每组维度的频率: θ_i = base^(-2i/d)
    freqs = 1.0 / (base ** (torch.arange(0, head_dim, 2).float() / head_dim))
    
    # 位置 × 频率 = 旋转角度
    angles = positions[:, None] * freqs[None, :]  # [seq_len, head_dim/2]
    
    # 构造 cos/sin 表
    cos = torch.cos(angles).unsqueeze(-1)  # [seq, dim/2, 1]
    sin = torch.sin(angles).unsqueeze(-1)
    
    # 将 q/k 拆成 (x_even, x_odd) 对，应用 2D 旋转
    q_even, q_odd = q[..., 0::2], q[..., 1::2]
    k_even, k_odd = k[..., 0::2], k[..., 1::2]
    
    # 旋转: [cos -sin; sin cos] × [x_even; x_odd]
    q_rot = torch.stack([q_even * cos - q_odd * sin,
                         q_even * sin + q_odd * cos], dim=-1).flatten(-2)
    k_rot = torch.stack([k_even * cos - k_odd * sin,
                         k_even * sin + k_odd * cos], dim=-1).flatten(-2)
    
    return q_rot, k_rot

05 频率分层设计哲学

RoPE 的频率 $\theta_i$ 构成一个几何级数，从高到低递减。 这种设计赋予了 RoPE "多尺度望远镜"的能力——不同维度负责不同粒度的位置信息。

图 3：RoPE 频率谱——多尺度位置编码
高频维度旋转快，编码精细的局部位置（相邻 token 关系）；低频维度旋转慢，编码粗粒度的全局位置（远距离关系）。

🔎 高频维度（小的 i）

$\theta_i$ 大，旋转快，约每 6.28 个 token 完成一个完整旋转周期。负责编码局部、精细的位置关系——"这两个词相邻吗？"

🌐 低频维度（大的 i）

$\theta_i$ 小，旋转慢，在整个训练长度内可能只扫过一小段弧。负责编码全局、粗粒度的位置关系——"这两个词相距很远吗？"

06 致命问题：长度外推失败

RoPE 虽然编码了相对位置，但并不意味着可以无限外推。训练时模型只在 $[0, L_{\text{train}}]$ 范围内见过旋转角度， 推理时超出这个范围就会出现严重问题。

图 4：RoPE 外推失败的两个原因
左：训练范围内的正常状态。右：超出训练范围后，高频维度遇到 OOD 相位，低频维度失去远距离区分能力。
⚠️ 实际影响

例如 LLaMA-2 训练在 4096 token，直接推理到 32768 时，perplexity 急剧上升，输出完全不可用。必须通过 RoPE 扩展技术来突破训练长度限制。

07 方案一：位置插值 PI（2023.6）

论文： Extending Context Window of Large Language Models via Position Interpolation（Chen et al.）

核心思想：压缩位置索引

最直接的思路：如果超出的位置是问题，那就把所有位置等比例压缩回训练范围内。 例如 4K → 32K 扩展，所有位置除以 8，模型看到的旋转角度始终在训练范围内。

位置插值：线性压缩 $$ m' = \frac{m}{s}, \quad s = \frac{L_{\text{target}}}{L_{\text{train}}} $$
图 5：Position Interpolation 原理

✅ 优点

简单直接，只需少量微调（约 1000 步）即可适配新长度。Llama 2 的 4K→32K 扩展采用了此方案。

❌ 缺点

所有频率维度均匀压缩——高频维度（编码局部信息）也被压缩，导致 4 个物理 token 共享一个角度槽位，短上下文性能下降明显。

08 方案二：NTK-aware RoPE（2023.6）

来源： bloc97 在 Reddit r/LocalLLaMA 社区发布（非正式论文），借鉴 Neural Tangent Kernel 理论。

核心洞察：不同频率需要不同对待

PI 的问题在于"一刀切"地压缩所有维度。NTK-aware 的关键洞察是： 高频维度应该外推（保持不变），低频维度才需要插值（压缩）。

💡 直觉解释

高频维度在训练范围内已经完成了多个完整旋转周期，它们对位置的编码已经"饱和"，超出范围不会产生全新的信息——所以可以安全外推。低频维度在训练范围内只扫过一小段弧，超出后角度差异趋零——所以需要压缩。

方法：修改 Base 而非位置

NTK-aware 不是缩放位置索引，而是修改 RoPE 的 base 值：

NTK-aware：修改 base 频率 $$ b' = b \times s^{\,d/(d-2)} $$

这等效于让低频维度旋转更慢（压缩角度），高频维度几乎不受影响。

图 6：PI vs NTK-aware 对不同维度的处理对比
PI 对所有维度一刀切压缩；NTK-aware 区分高低频但仍然较粗；YaRN 进一步精细化分为三段处理。

✅ 优点

无需微调即可实现 4-8 倍扩展。Code Llama 和早期 Qwen 采用了此方案。

⚠️ 局限

对所有维度一刀切地修改 base，精度有限；超过 8 倍后效果显著下降。

09 方案三：YaRN（2023.9）

论文： YaRN: Efficient Context Window Extension of Large Language Models（Peng et al., Nous Research）

YaRN 是对 NTK-aware 的精细化升级，也是 2023-2024 年最主流的长上下文扩展方案。 它的核心创新是将 RoPE 维度按波长分为三组，分别应用不同策略——即 NTK-by-parts。

分频段差异化处理

YaRN 核心逻辑（伪代码）
for each frequency dimension i:
    wavelength_i = 2π / θ_i

    if wavelength_i < L_train / 32:        # 高频维度（波长短，旋转快）
        scale_i = 1.0                     # → 不插值，直接外推
    
    elif wavelength_i > L_train / 1:     # 低频维度（波长长，旋转慢）
        scale_i = s                        # → 完全插值，压缩到训练范围
    
    else:                                # 中间维度
        scale_i = ramp(wavelength_i)       # → 渐进式斜坡过渡

    θ'_i = θ_i / scale_i
YaRN 频率缩放公式 $$ \theta'_i = \theta_i \cdot s^{-\,\text{ramp}(\lambda_i)}, \quad \text{ramp} \in [0, 1] $$

额外创新：注意力温度缩放

长序列下注意力会过度分散，YaRN 引入温度因子来增加注意力锐度：

注意力温度缩放（mscale） $$ \text{Attention} = \text{softmax}\!\left(\frac{QK^T}{t \cdot \sqrt{d}}\right), \quad t = 0.1 \cdot \ln(s) + 1 $$

10 方案四：ABF 大 Base 频率（2023）

论文： Extending LLMs' Context Window with 100 Samples（Zhang et al.）

ABF（Adjusted Base Frequency）提出了一个惊人简单的方案： 直接增大 RoPE 的 base 值（如从 10000 调到 500000），配合注意力缩放。

核心原理

base 越大，所有维度的旋转速度越慢——等效于在不改变位置索引的情况下，让模型在更长的序列上仍能保持角度差异。 特别是低频维度（原本旋转极慢），增大 base 后在长序列上仍能保持可区分的角度差。

图 8：不同 Base 值下的旋转角度对比
🚀 实际影响

Llama 3 将 base 从 10000 提升到 500000，原生支持 128K 上下文。这是目前最简单有效的长上下文方案——只需修改一个配置参数。Qwen 2.5/3 和 Mistral Large 2 更进一步使用 base = 1,000,000。

11 百万 Token：LongRoPE（2024.2）

论文： LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens（Microsoft Research, ICML 2024）

LongRoPE 首次将预训练 LLM 的上下文窗口扩展到 2048K（200万）token——从 4K 到 2M，512 倍跨越。 它通过三大核心创新实现了这一突破。

创新一：非均匀 RoPE 插值

LongRoPE 发现 RoPE 中存在两种非均匀性，之前的方法都没有充分利用：

📊

维度非均匀性

不同 RoPE 维度需要不同的缩放因子。低维（高频）需要更少插值，高维（低频）需要更多插值——但最优解取决于目标长度。

🎯

位置非均匀性

序列起始的 token 位置可以不插值（直接外推），因为它们对应高频旋转，在训练中已经见过完整周期。

使用进化搜索算法为每个维度和位置段搜索最优的非均匀缩放因子。仅靠非均匀插值（不微调），就能实现 8 倍扩展。

🏆 LongRoPE 的实际影响

Llama 2 7B：4K → 2048K（512 倍），仅 1000 步微调。Phi-3-128k 系列的 128K 变体均使用 LongRoPE。后续 LongRoPE2（2025.2, ICML 2025）进一步优化，在 Llama-3 8B 上达到 128K，保留 98.5%+ 短上下文性能。

12 2025-2026 最新进展

MrRoPE：统一理论框架（ICLR 2026）

提出基于混合基数系统转换的统一理论框架，将 PI、NTK、YaRN 等所有 RoPE 扩展方法统一为不同的"基数转换策略"。 基于此理论提出的 MrRoPE-Pro 免微调方案，在 128K Needle-in-a-Haystack 测试中保持 85%+ 召回率， 在 Infinite-Bench 上准确率是 YaRN 的两倍以上。

多模态 RoPE：从 1D 到多维

📷

M-RoPE Qwen2-VL, 2024.9

将 RoPE 频率维度分为三段，分别编码时间(t)、高度(h)、宽度(w)。文本 token 三轴共享递增值→退化为标准 1D RoPE；视觉 token 用 h/w 编码 2D 网格位置。

🎦

VideoRoPE 2025.2

针对视频场景优化：将时间维度分配给低频维度（避免周期性震荡），采用对角空间布局保持对称性，可调时间间距解耦时空索引。

🧬

MHRoPE & MRoPE-I ICLR 2026

Qwen 团队系统性分析多模态 RoPE，提出三条设计准则：位置一致性、全频段利用、文本先验保持。MHRoPE 按注意力头分配频率，MRoPE-I 采用交错分配。

🔐 一句话总结

RoPE 能成为 LLM 位置编码的绝对主流（2025 年开源 7B+ 模型中采用率约 92%）， 根本原因是它在数学上的优雅性：通过旋转操作，在不增加任何参数、不修改 Attention 结构的前提下，让注意力分数自动编码相对位置。 从 4K 到百万 token 的跨越，本质上是"简单的均匀压缩"逐步演进到"精细化的非均匀优化"的过程。
