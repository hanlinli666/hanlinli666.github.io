2026-08-19 约 18 分钟 DeepSeek V4 Pro Harness Overfitting Self-Consuming Loop

01引言：深夜上线与「降智」热搜

8 月 12 日深夜，DeepSeek 没有发布会、没有预热、连一份正经的更新日志都没有，只是悄悄把 API 文档里 V4 Pro 的状态从「预览」改成了「正式版」，版本号 0813。24 小时之内，开发者社区炸了——不是因为太好，而是因为太「差」：大量实测发现，这个输出价格是 Flash 三倍的模型，在日常任务里和 Flash 几乎没区别，长程代码任务还会中途「躺平」。「降智」两个字，瞬间冲上 AI 圈热搜。

但这个故事最有意思的部分，恰恰发生在「降智」定性之后。社区顺藤摸瓜，在两天内完成了一场教科书级的尸检：同一套模型权重，换个运行环境，分数从 91 分拉到 99 分；一凌晨合入 Harness 仓库的 commit，直接坐实了病灶。结论不是「模型不行」，而是一个更刺耳的判断——它过拟合了自己的训练环境。

TL;DR
  • V4 Pro-0813 大概率没有「降智」，而是过拟合了 RL 训练时的环境——DeepSeek Harness 的 Minimal 配置（一个持久 shell + 一个文件编辑器，共两件工具）。
  • 换回训练时的环境，分数从 91 回到 99。这是社区第一次把「harness 级过拟合」从猜测变成可复现的实锤：证据链包括一行 commit、一组对照实验、一个完美的对照组模型（Flash）。
  • 它不是孤例。独立评测显示 Codex、Claude Code、Qwen Code 的 harness 都对自家大模型存在耦合优化；DeepSeek 只是第一个症状足够戏剧化、证据链足够完整的。
  • 把镜头拉远：后训练还没有到经典意义的过拟合上限（数据规模收益仍在），但 self-generate / self-train 循环 + 固定 harness 环境的组合，正在一个新的维度上制造过拟合——上下文维度。

2026-07-31

更小的 V4 Flash（284B / 13B 激活）抢先转正，且经过再训练的 Flash 在多个 agent / 编程基准上反超了四个月前的 Pro Preview。官方承诺 Pro 转正「很快跟进」。

2026-08-12 深夜

2.1神秘的三张脸

就在质疑声最响的时候，社区发现了更离奇的现象：调用同一个 deepseek-v4-pro 接口，换个 IP、新建个会话，模型的「说话风格」会变。有人总结出三张脸——

一种以 Let me... 开头，像之前的 Preview 版；一种说 The user wants me...，像 Flash；还有一种用 We need... 最多、推理最强，被社区封为「上帝模式 0813」。大家一度怀疑 DeepSeek 在单个 API 后面藏了三个模型偷偷路由。这个猜测后来被证伪了，但「三张脸」这个观察，事后看正是整个病例里最重要的症状——我们在第 5 节会回来解释它。

03实锤证据：一行 commit 与四组数字

真正的突破口，是 DeepSeek 同步开源的 Agent 运行时——DeepSeek Harness（DSH）。8 月 10 日，也就是正式发布前两天，Harness 代码库里悄然合入了一个提交：

fix(preset): align minimal agent with RL composition

翻译成人话：让极简模式与强化学习时的训练环境对齐。官方评测 V4 Pro 用的那个「极简环境」，必须和模型训练时所处的环境一模一样，模型才能发挥出真正水平。这行 commit 等于官方自供：RL 训练环境就是 Minimal 那套配置——

# apps/cli/config/agent-presets/minimal/agent.cordis.yml（节选）
- id: persona
  config:
    text: You are a helpful software engineer assistant.  # 就这一句开场白
    complete: true            # 它是「全部」，不再叠加任何话
    includeRuntimeContext: false  # 不注入运行时上下文快照
- id: persistent-shell       # 工具一：持久 bash
- id: str-replace-editor     # 工具二：字符串替换编辑器

社区顺着这条线索做了实验。同一个 V4 Pro，放在 Harness 的不同模式里跑 Project2（越接近训练环境，分数越高）：

同一套权重，只换运行环境。「两阶段锚定」= 第一轮按 Minimal 喂、模型开始调用工具后再解锁 Standard 全套工具。

模型没换，换的是它第一次「睁眼」看到的环境。差距一目了然。但真正让「过拟合」定性站住脚的，是下面三条证据链的闭环：

证据链
  • commit 自供：RL 训练环境 = Minimal 配置（一句话 persona + 两件工具，上下文零噪声）。评测高分环境恰好就是训练环境。
  • Flash 对照组：V4 Flash 在所有 Harness 模式下分数稳定在 90–95，切极简模式毫无变化。排除了「Harness 有魔力」的解释——这是 Pro 的专项 agent 后训练独有的病。
  • 两阶段不塌：先 Minimal 起手、模型开始调工具后再灌入 25 件工具，分数不回落。说明不是能力缺失，而是冷启动时初始 token 分布决定后续推理轨迹——点火点歪了，不是发动机没马力。
一个更隐蔽的推论

官方把 Minimal 定义为「跑基准测试的标准环境」，而 Minimal = RL 训练环境。这等于：所有官方跑分都在训练分布内进行。这比传统的 benchmark 题目泄漏更隐蔽——不是题泄漏了，是环境泄漏了。第三方（如 Artificial Analysis）测的才是真正的 OOD 分数。

04论点一：后训练远未过拟合

先把镜头拉远。一个流行的判断是：受模型规模、数据量等限制，此前的后训练远远没有达到经典意义的过拟合，所以各家的各种后训练策略都有效，增大数据规模的效果也远未触顶。这个判断基本成立，而且有一批 2025–2026 年的论文给出定量支撑：

4.1RL 后训练有自己的 scaling law，且还没撞墙

对 Qwen2.5 全系列（0.5B → 72B）的系统实验给出了几条结论：固定算力预算下，大模型少步训练优于小模型多步训练；在数据受限场景下，重复利用高质量数据依然有效——最终性能主要由优化步数而非样本唯一性决定。学习效率 k(N) = Kmax / (1 + N₀/N) 呈饱和曲线，但那是「效率」饱和，不是「收益」归零。

快手开源的 Klear-AgentForge 管线（Qwen3-8B 起步的完整 agent 后训练）也展示了同样的趋势：SFT 数据从单轨迹扩到多轨迹，SWE-Bench 持续上涨，未见平台期。「堆 agent 轨迹数据还有收益」是各家共识，不是错觉。

4.2为什么各家策略「都有用」：RL 在把模型往泛化推

一篇很有意思的污染研究（arXiv 2601.06103）做了受控实验：把基准测试题注入预训练数据，再分别过 SFT 和 GRPO。结果——SFT 只在污染任务上涨分（纯记忆化），而 GRPO 能把泄漏转化为对未污染任务的泛化增益。换句话说，RL 类后训练至今仍在把模型往「泛化」方向拽，这为「各家 RL 策略都有用」提供了机理层面的解释。

但要修正一个变量

「上限」不在数据量，而在多样性。RL scaling 的饱和 + 输出熵坍缩（见下节）意味着这个游戏的真实天花板是探索能力的耗尽，不是 token 不够。一旦训练环境的多样性被锁死，堆再多数据也只是在同一个分布里打转。

05论点二：用力过猛与自我加速

第二个判断是：Pro 这次的问题来自「用力过猛」——大量 Agent Harness 构建 + self-generate / self-train，大大加快了过拟合甚至崩溃的风险。方向对，但值得把这个机理拆得更精确，因为这里的「过拟合」和经典统计学习里的不是一回事，而且结构性地更危险。

5.1Agent RL 的轨迹，是所有自训练循环里最窄的一种

纯文本的 self-train（STL）至少还保留了开放域的表层多样性。而 agent RL 的训练数据是模型在同一个环境里滚出来的轨迹：每次 rollout 的 system prompt、工具 schema、消息格式逐字相同。这意味着前缀上下文（harness 配置）在训练分布里是一个零方差常量。

固定环境同一套 system prompt 与工具 schema
→
rollout模型在环境内生成轨迹
→
奖励benchmark 通过率
→
更新策略权重强化这套轨迹
循环往复：环境前缀逐字不变 → 模型学到的不是「如何用工具」，而是「看到这套开场白时如何用工具」。Harness 从外挂变成了条件策略的一部分。

这就是 Flash（没做重 agent 后训练）不受影响、而 Pro 中招的原因。

5.2这不是经典过拟合，是 policy / entropy collapse

ICLR 2026 的 Self-Critique 论文给出了关键观察：RL 后训练会使输出熵坍缩到稀疏模式——pass@1 涨、pass@k 跌，模型收敛到窄推理路径。回到第 2 节的伏笔：「三张脸」正是这个——不同的初始上下文把坍缩后的窄策略「选」到不同的模式上。极简模式高分不是玄学加成，是把模型推回了训练分布；Standard 模式低分是纯 OOD。

所以严格说，「Pro 在极简模式下过拟合」这个表述应该反过来看：模型过拟合于极简环境，在一切非该环境下性能坍塌。

5.3能力极化：崩溃不是均匀退化

2026 年的新工作（KITE）发现，collapse 不是均匀的性能下滑，而是能力的极化——合成数据强化已有强项、进一步侵蚀弱项。对 agent 训练这尤其致命：模型在「标准 agentic loop」上无限自我强化，在「陌生开场 / 陌生工具集」上加速荒废。Harness 锁定，就是能力极化在上下文维度上的投影。

5.4「用力过猛」的定量侧写

四个多月的专项 agent 后训练，换来 DeepSWE 62.7 / Terminal-Bench 2.1 87.9 的官方成绩，代价是 CoT 对自身训练分布的过拟合：裸 API 下推理时好时坏、长程任务中途放弃、输出风格随初始上下文漂移。用一句话概括这个训练策略：在一条一维的环境坐标轴上做了极限扫描——效率极高，泛化面极窄。

06Self 哲学：自我吞噬的循环

把 DeepSeek 事件放进「self-*」这条更大的技术脉络里，它的位置会更清晰。过去三年，后训练的主线其实是一场用自己喂自己的运动：

阶段代表工作「自我」的浓度
Self-Instruct（2022–23）用模型生成指令数据做 SFT自我只出题，人类数据仍为主食
SPIN / Self-Rewarding（2024）自我对弈微调；自我打分当奖励「自我」进入监督信号
Absolute Zero / R-Zero（2025）proposer–solver 从单一基座共演化，零人类任务循环完全闭合
Agent RL（2025–26）固定 harness 内 self-rollout + 通过率奖励循环闭合 且环境冻结
RSI 展望（2026）部署期自我改写 harness、自我做研究循环闭合且自我修改脚手架

「自我浓度」：训练信号中源自模型自身输出的比例，以及循环闭合的程度。

6.1一个反直觉的理论锚点：自我对弈的均衡是「自己」

SPIN 的收敛性证明常被当作好消息引用，但换个角度读它很吓人：self-play 微调可证明地收敛到模型自身的分布。换句话说，自我对弈的数学终点不是「更好」，是「更像自己」。每一代迭代都在消耗分布的方差——这不正是 Shumailov 等人在 Nature 2024 里描述的 model collapse（尾部消失、方差坍缩）的动力学吗？

6.2验证层级：self 循环的隐秘主角

2026 年一篇综述了 1250 篇 arXiv 论文的 RSI survey 给出了最有用的分析框架：验证层级。已证明的自改进强度沿这个层级递减：

形式化验证（最强）→ 程序化验证 / 可验证奖励 → LLM 裁判 → 内在自我评估（最弱）

—— 自改进的强度跟随验证信号的强度；失败模式（自我确认循环、model collapse、多样性坍缩）都源于对层级的违反

用这个框架看 agent 训练：它的 verifier 是「环境内通过率」——只验证「在这个环境里能不能完成任务」，从不过问「换个环境还行不行」。整个循环在优化一个单环境指标，自我强化到 99 分，同时 OOD 能力静默流失。DeepSeek 事件只是这个流失第一次被社区撞见。

6.3健康循环的三个条件（以及 DeepSeek 如何全部踩线）

综合 2026 年的几篇 self-play 论文（ICML 2026 的 learnable-information-gain 框架、SOAR、Tufa 的 Self Rewarding Self Improving），一个自训练循环要健康，至少要满足：

条件论文出处Pro 的踩线方式
可学习信息增量单调上升，否则 plateauICML 2026（PROPOSER / SOLVER / VERIFIER 三位一体）环境冻结 → proposer 探索空间被锁死，信息增益单调递减
真实数据恒定配比回流，保证 recursive stabilityICLR 2025 理论工作：恒定比例真实数据可保证 STL 收敛self-trajectory 占比随 agent 后训练飙升，真实回流不足
多样性 / 探索保持，防熵坍缩与极化Self-Critique（ICLR 2026）：熵坍缩、pass@k 下降「三张脸」就是熵坍缩的可见指纹

文献里反复出现的另一个失败模式叫 self-delusion：verifier 自己失准后，整个循环会自信地强化错误。Tufa 的解法是利用「生成难、验证易」的不对称性；SOAR 的发现是 grounded reward（以学生在留出难题上的真实进步为准）优于任何内在可学习性奖励。

6.4两个趋势相乘，context 级过拟合只是时间问题

最后把视野拉到最宽。今天的后训练正在同时发生两件事：

其一，「自我」浓度上升——每一代模型都在吃上一代（或自己）的输出；其二，部署环境越来越定制化——每家一套 harness、一套开场白、一套工具目录。两个趋势相乘，得到一个结构性结论：上下文级别的过拟合不是某家的失误，而是整个 self-train 时代的系统性风险。谁先在随机化的环境里做训练，谁就先免疫。

07不止 DeepSeek：谁还有这毛病

那句被很多人引用的话值得展开：DeepSeek 不是第一个有这毛病的，是第一个症状足够戏剧化、证据链足够完整以至于被社区逮到实锤的。它撞上了四个条件同时成立：开源权重、Harness 同步开源、那行 commit 留痕、还有一个完美的对照组模型（Flash）。闭源厂商即使有同样的病，也没有尸检条件。但间接证据遍地都是：

7.1厂商 harness 全面「偏科」：Delangue 转发的 10-harness 研究

2026 年 8 月初，Joël Niklaus 做了一组后来被 HuggingFace CEO Clément Delangue 放大的实验：10 个 agent harness × 2 个模型（GLM-5.2 与 Gemma-4 26B-A4B），同一批 SWE-bench Pro 250 题。结论相当残酷——

  • 同一模型只换 harness，pass@1 从 23% 摆到 52%（GLM-5.2）、15% 到 36%（Gemma-4）：比多数模型版本升级带来的差距还大；
  • 两个模型的 harness 排名相关系数 −0.05——harness 排行榜完全不可迁移；
  • Delangue 的原话：「Codex is overoptimised for large models.」
HarnessGLM-5.2 排名Gemma-4 26B 排名迁移表现
Codex（OpenAI）29↓ 7 位
Claude Code（Anthropic）37↓ 4 位
Qwen Code（阿里）46↓ 2 位
crush（模型无关）71↑ 6 位
opencode（模型无关）82↑ 6 位
pi（模型无关）94↑ 5 位

所有厂商自研 harness 换到别家 / 小模型上集体下滑，模型无关的 harness 集体上升。26B 模型配对 harness（36%，$0.84/题）能逼近 744B 模型配错 harness 的水平。

注意这里的方向和 DeepSeek 案例相反但本质相同：DeepSeek 是模型过拟合 harness，这里是 harness 过拟合模型。合起来说明 model + harness 已经被共同优化成一个不可分割的复合系统——「Agent = Model + Harness」正在从工程等式变成耦合契约。

7.2同模型换 harness 的摆动幅度：Terminal-Bench

Terminal-Bench 2.0 榜单上的名场面：同一个 Claude Opus 4.6，在自家 Claude Code 的 harness 里只有 58.0%，换 ForgeCode 跑到 81.8%——23.8 个百分点的差距，全部来自脚手架。

7.3零散的旁证

  • sentdex 实验：同一套 V4 Flash 权重，博主自制简陋工具过 44/89 题，换社区完整 Harness 后 64/89——多过 20 题，权重一字未动。
  • 「三张脸」与锚定效应：模型把第一次看到的工具列表当思考锚点。社区开源的 dsh-anchored-standard 就是利用这一点打的补丁：第一轮按 Minimal 喂，稳住推理轨迹后再解锁全套工具。
  • 97% 的输入 token 是重发的会话前缀（同上研究）——这意味着 harness 的每一处设计都在和模型的上下文分布深度纠缠，也解释了为什么 prompt caching 成了成本命脉。

7.4自查清单：你的模型是否「认环境不认任务」

四个症状
  • 官方跑分与第三方 / 裸 API 成绩差距悬殊，且官方环境恰好等于训练环境；
  • 换 harness 出现断崖式掉分，而非平滑衰减；
  • 同家族小模型（未做同款后训练）在各环境下表现稳定——它是天然对照组；
  • 输出风格随初始上下文（开场白、工具目录）切换——熵坍缩的指纹。

按主题分组，每篇附一句话结论。标 核心 的是理解本次事件最直接的读物。

09展望：harness-agnostic 时代

往前看，这个事件会留下几条路线的竞争：

9.1训练侧：对 harness 做数据增强

最直接的解法是把「环境」从一个常量变成一个随机变量：训练时随机化 persona、工具集、上下文前缀、消息顺序——相当于对 harness 做数据增强。deep 的教训等于替全行业做了一次消融实验：固定环境训练 = 单环境过拟合；那么随机环境训练理应换来 harness 无关的泛化。谁先做出 harness-agnostic 的 agent 后训练管线，谁就同时拿下「官方跑分」和「裸 API 体验」两个战场。

9.2部署侧：把锚定显式化

在训练侧解决之前，部署侧已经在打补丁：dsh-anchored-standard 的两阶段方案（先 Minimal 锚定、再解锁全套工具）证明锚定可以显式设计。把它产品化成 context warmup 机制——先给模型一个干净的开场，稳住推理轨迹后再扩上下文——是从下游为上游训练分布的窄化买单。

9.3评测侧：harness 披露成为标配

当 harness 引起的方差超过模型换代带来的差距，只报分数不报环境就是在误导。约束主导论一文提出的披露卡（harness 配置规格 + 扰动压力测试）大概率会演变成社区共识：同一模型至少要报「自家环境」和「中立环境」两组成绩，差距本身就是一个新的评测维度——环境敏感性，也许该成为 agent 模型的标配体检项。

9.4生态侧：开源权重，事实封闭

更冷峻的一层：每家模型绑定自家 harness、换 harness 即降智，这实质上是用开源权重实现了事实上的生态封闭。权重你随便拿走，能力留在我的脚手架里。「Agent = Model + Harness」从工程等式变成耦合契约的那天，开源的定义就被悄悄改写了。

10后记：过拟合只是被看见了

最后修正一下自己最初那个框架。「之前的后训练远未过拟合，所以各家策略都有用」——成立，但要补一个变量：不是没人过拟合，而是过拟合的维度还没被暴露。传统后训练（对话、推理）的训练环境 = 部署环境——都是聊天窗口，过拟合被部署的同质性掩盖了。Agent 时代第一次让「训练环境 ≠ 部署环境」成为常态（harness 生态碎片化），这才把上下文级别的过拟合暴露成一个真问题。

而在这个维度上，DeepSeek 0813 是第一个被逮到实锤的，但 self-loop 的物理规律对每家一视同仁：

Self-loop 的燃料是环境的多样性。当模型开始吃自己产出的数据，它就在消耗自己分布的方差——每一次迭代，世界都更像它自己一点。过拟合不是意外，而是这个过程第一次被肉眼看见。
