为什么要有 Attention

2017 年之前，处理序列的主力是 RNN / LSTM。它们像人逐字阅读：读一个词、更新一次记忆、再读下一个。这个设计有个致命的物理瓶颈——无论句子多长，中间那团"记忆"始终是固定大小的向量。句子一长，开头的信息要么被挤出去，要么被稀释成一锅粥，这就是传说中的"长程依赖问题"。

2014 年 Bahdanau 等人在机器翻译里给出了第一个答案：让解码器在每一步生成时，回头看一眼整个源句子，自己决定该重点看哪里。这就是注意力的雏形。2017 年《Attention Is All You Need》更激进：把 RNN 直接扔掉，注意力本身就是全部。

它的核心思想一句话就能说完：

核心思想

按需分配注意力——对相关的信息多看几眼，对无关的信息少看几眼，然后把看到的东西加权平均拿回来用。

这个"加权平均"看似平平无奇，但因为它对每一对位置都直接建立连接（任意两个 token 之间的路径长度都是 1），长程依赖的传播问题被一举解决；又因为所有位置的权重可以并行算出，RNN 的串行瓶颈也消失了。代价嘛——每一对位置都要算一次相似度，计算量和显存都是 $O(n^2)$。这个 $n^2$ 是后面所有故事的起点，先记在这里。

注意力的基本盘：Q、K、V 与那个公式

图书馆检索的比喻

想象你去图书馆查资料：

  • Query（查询）：你心里的问题；
  • Key（键）：每本书书脊上的索引标签；
  • Value（值）：书的正文内容。

你拿着 Query 和每本书的 Key 逐一比对，得到匹配分数；分数越高，从这本书里"抄"的内容越多。最后把所有书抄来的内容按匹配度加权混合，就是你这次检索的收获。注意：匹配用 Key，取内容用 Value——打分和取货是分开的，这让"怎么检索"和"检索到什么"可以独立学习。

Scaled Dot-Product Attention：一步步算

把上面的比喻写成公式，就是深度学习里出镜率最高的一行：

$$ \text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V $$

别被它吓到，拆开看每一步都极其朴素。设 $Q\in\mathbb{R}^{n\times d_k}$（$n$ 个查询），$K,V\in\mathbb{R}^{m\times d_k}$（$m$ 个键值对），流程是：

逐个步骤过一遍：

  1. 打分：$S = QK^{\top}$，第 $i$ 个 query 和第 $j$ 个 key 做点积，衡量"这俩有多匹配"。点积就是无界的余弦相似度加强版——既看方向，也看模长。
  2. 缩放：除以 $\sqrt{d_k}$，防止分数过大（下面马上解释）。
  3. 掩码（可选）：把不该看的位置（比如未来的 token）置为 $-\infty$，softmax 之后权重正好是 0。
  4. 归一化：对 每一行（也就是每个 query 对所有 key 的分数）做 softmax，变成非负、和为 1 的注意力分布 $A$。
  5. 取货：$O = AV$，输出是所有 value 的凸组合。

用 NumPy 写出来不到十行，麻雀虽小五脏俱全：

import numpy as np

def attention(Q, K, V, mask=None):
    # Q: (n, d_k)   K: (m, d_k)   V: (m, d_v)
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)          # 1) 打分 + 2) 缩放  -> (n, m)
    if mask is not None:
        scores = np.where(mask, scores, -np.inf)   # 3) 因果掩码
    A = np.exp(scores - scores.max(-1, keepdims=True))
    A = A / A.sum(-1, keepdims=True)         # 4) 行 softmax
    return A @ V                              # 5) 加权取值    -> (n, d_v)
一个常被忽略的细节

softmax 里的 减 max 不是可选项：指数函数爆起来没有上限，长序列 + 大分数必然溢出。减去每行最大值后结果数学上完全等价、数值上岁月静好。后面 FlashAttention 的 online softmax 也是围绕这个 max 做文章。

为什么要除以 √d_k

假设 $q$ 和 $k$ 的各个分量是均值 0、方差 1 的独立随机变量，那么点积 $q\cdot k=\sum_{i=1}^{d_k}q_i k_i$ 的方差是 $d_k$。当 $d_k = 128$ 时，点积的标准差约 $\sqrt{128}\approx 11$——分数动辄几十上百。

问题出在 softmax：输入一旦拉开差距，输出就接近 one-hot（比如 $[0, 0, 1, 0]$）。one-hot 意味着"只看一个位置"，而 softmax 在饱和区的梯度几乎为零，训练就停摆了。除以 $\sqrt{d_k}$ 恰好把方差拉回 1，让 softmax 待在梯度健康的"温和区"。

记忆钩子

点积方差随维度涨（$\text{Var}=d_k$），除以 $\sqrt{d_k}$ 就是方差归一化，救的是 softmax 的梯度。

三种常见口味：Self / Cross / Causal

同样的公式，Q/K/V 从哪来，决定了注意力的"口味"：

  • Self-Attention（自注意力）：Q、K、V 都来自同一个序列。序列里的每个 token 互相看，适合理解类任务。BERT 全程用它。
  • Cross-Attention（交叉注意力）：Q 来自序列 A（如解码器），K/V 来自序列 B（如编码器）。翻译模型里"译文看原文"就是它；Stable Diffusion 里图像块去 attend 文本 token 也是它。
  • Causal Self-Attention（因果自注意力）：自注意力 + 上三角掩码，每个 token 只能看自己和过去。GPT 们的自回归生成全靠它，也是 KV Cache 故事的主角。

复杂度账单

一次 self-attention（$n$ 个 token，维度 $d$）：

  • 计算量：$QK^\top$ 是 $n\times n\times d$，$AV$ 又是 $n\times n\times d$，合计 $O(n^2 d)$；
  • 显存：朴素实现要把 $n\times n$ 的分数矩阵和权重矩阵都写出来，$O(n^2)$。

序列长度翻倍，计算量与显存都 ×4。$n^2$ 是注意力的"原罪"——长上下文、大 batch 的一切优化，本质上都在和这个平方项搏斗：要么少存（GQA / MLA / 滑窗），要么少读写（FlashAttention / PagedAttention），要么干脆少算（稀疏 / 线性注意力）。把这条主线记牢，后面的所有章节都是它的注脚。

MHA：多头注意力

一个头不够看

单头的注意力只有一种"打分姿势"，所有 token 用同一套 $W^Q, W^K, W^V$ 投影，等于只从一个视角理解句子里错综复杂的关系。但语言里的关系是多层面的：有的头在盯句法依存（主谓一致），有的头在数位置（相邻 token），有的头在追指代（it 指什么）……

于是 2017 年的 Transformer 干脆并行放 $h$ 个头，各自学各自的投影矩阵，各看各的子空间，最后把结果拼起来。这就是 Multi-Head Attention（MHA）：

$$ \text{head}_i=\text{Attention}(QW_i^Q,\;KW_i^K,\;VW_i^V) $$ $$ \text{MHA}(Q,K,V)=\text{Concat}(\text{head}_1,\dots,\text{head}_h)\,W^O $$

计算流程

具体过程以 Llama-3-8B 一层为例（$d_{model}=4096$，$h=32$）：

  1. 整体投影：$X\,(n\times 4096)$ 分别乘 $W^Q, W^K, W^V$（各 $4096\times 4096$），得到 $Q,K,V$；
  2. 切头：沿最后一维切成 32 份，每头 $d_k = d_v = 4096/32 = 128$。注意"切头"只是 reshape，不引入参数；
  3. 各头独立做 scaled dot-product attention，各自输出 $n\times 128$；
  4. 拼接成 $n\times 4096$，再过 $W^O$（$4096\times 4096$）做头间混合。

几个容易踩坑的细节

  • MHA 并不比"单头 4096 维"贵。每个头的投影是 $d_{model}\times d_k$，$h$ 个头加起来正好还是一个 $d_{model}\times d_{model}$ 的矩阵。参数量、计算量与单头同规模版本完全相同——多买的是"视角"，不是"面积"。
  • 每个头是低维子空间里的注意力：128 维的相似度度量。所以 MHA 隐式假设注意力模式是低秩的——这个视角对后面理解 MLA 的低秩压缩至关重要。
  • 头的数量是超参：太小表达力不足，太大每头维度太低反而学不好。工程惯例 $h\in\{32, 64\}$、$d_h\in\{64, 128\}$，且为并行友好取 2 的幂。
  • 因果掩码对每个头同样生效；训练时所有头并行算，就是一堆 batch 化的矩阵乘。

优势与代价

MHA 的账本

优势：表达力天花板高（每头自带一套"检索系统"），是所有变体比拼质量的基准线；实现简单、并行度高。

代价：推理时 KV Cache 按 $\times h$ 膨胀——每层每个 token 要为每个头都存一份 K 和 V。70B 级模型（如 Llama-2-70B，80 层 × 64 头 × 128 维）每个 token 要存 $2\times 80\times 64\times 128 = 1.3\text{M}$ 个数，bf16 下约 2.6 MB/token——32K 上下文就是 85 GB，比模型本体还大。这就给下一章的"缩水运动"埋下了全部伏笔。

KV 头的精简史：MQA 与 GQA

动机：先把 KV Cache 拉出来遛一遛

要理解 MQA / GQA 为什么出现，得先把第 7 章的主角 KV Cache 提前请上台——它正是这一切的动机。

自回归模型生成文本时，每一步都拿当前 token 的 Query 去和所有历史 token 的 K、V 做注意力。如果每步都从头重算全部 K/V，计算量是 $O(t^2 d)$ 的重复劳动；显然该把算过的存起来复用，这就是 KV Cache。

这里有个关键的不对称性：

Q 是一次性消耗品，K/V 是耐用品

每个 token 的 $q$ 只在它自己那一步被用到，用完即弃；而每个 token 的 $k, v$ 会被之后所有步骤反复使用。所以只缓存 K/V，从不缓存 Q。

问题是 MHA 给每个头都配了一整套 K/V 投影，于是 cache 大小是 $2 \cdot L \cdot h \cdot d_h$（$L$ 为层数）。以 Llama-2-70B 为例（80 层 × 64 头 × 128 维，bf16）：每个 token 约 2.6 MB，32K 上下文就要 ~85 GB——比模型权重还大，显存直接爆炸。

于是一个很自然的念头冒出来：查询（Q 头）可以很多，但"资料库"（K/V）能不能少建几份、大家共享？

MQA：一个 KV 头伺候所有 Q 头

Multi-Query Attention（Shazeer, 2019，论文标题相当嚣张：《Fast Transformer Decoding: One Write-Head is All You Need》）把这个问题一步推到底：

  • 结构：$h$ 个 Query 头照旧，但只有 1 个 K 头 + 1 个 V 头，所有 Q 头共享；
  • 计算：每个 Q 头各自与同一份 K/V 做 scaled dot-product attention，其余流程（拼接、$W^O$）与 MHA 完全一致；
  • 效果：KV Cache 直接 除以 $h$。上面 70B 的例子里，2.6 MB/token 掉到约 41 KB/token；decode 阶段每步从显存读 cache 的带宽压力同步缩水，延迟肉眼可见地下降。

代价同样直白：所有 Q 头被迫共享同一套"检索系统"，不同子空间各看各的匹配模式被强行拉齐，模型质量有所回落（规模越大越明显）。所以 MQA 常见于对吞吐极其敏感的场景，代表用户：PaLM、Falcon、StarCoder。

GQA：分组的艺术

MQA 省 interspace 省得太狠，MHA 又太奢侈，Grouped-Query Attention（Ainslie et al., 2023）给出了中间态：把 $h$ 个 Q 头分成 $g$ 组，每组共享一套 K/V。

  • $g = h$：每组一个头独享 KV —— 退化回 MHA；
  • $g = 1$：所有头一组 —— 退化成 MQA；
  • KV Cache 缩小为 MHA 的 $g/h$（例如 64 Q 头、8 组 KV：缩小 8 倍）。

GQA 论文最漂亮的贡献是 uptraining：把已经训好的 MHA 模型"升级"成 GQA——同组 Q 头原本各自的 KV 投影权重取平均，作为共享投影的初始化，然后用原训练语料的 ~8% 继续训一小会儿。结果显示 uptrained GQA 质量几乎追平 MHA，速度接近 MQA。

MLA：DeepSeek 的降维打击

动机：换个维度想问题

GQA / MQA 省的是 KV 的份数，每一份 K/V 本身还是原样保存。DeepSeek-V2 的 MLA（Multi-head Latent Attention）换了个思路：K/V 本来就是 $h_t$ 经过投影矩阵算出来的产物——MHA 每头 $d_h$ 维、总共 $h\cdot d_h$ 维的 K/V，信息源头无非是 $d_{model}$ 维的隐藏状态。那凭什么要存"解压后"的完整 K/V？存压缩包不就行了？

这就是低秩压缩：把 K/V 联合压缩进一个潜在向量 $c^{KV}$，推理时只缓存它，用的时候再"解压"还原。

结构与计算

MLA 的完整公式（下投影 ↓、上投影 ↑）：

$$ c_t^{KV} = W^{DKV}\, h_t \qquad (\text{下投影：} d_{model} \to d_c,\ d_c = 512) $$ $$ k_{t,i}^{C} = W_i^{UK}\, c_t^{KV}, \qquad v_{t,i}^{C} = W_i^{UV}\, c_t^{KV} \qquad (\text{上投影还原出每头的 K / V}) $$

Q 侧如法炮制（主要为省训练时的参数与激活，Q 反正不缓存，对 KV Cache 无影响）：

$$ c_t^{Q} = W^{DQ} h_t, \qquad q_{t,i}^{C} = W_i^{UQ} c_t^{Q} $$

推理时只需缓存 $c_t^{KV}$（512 维）和下面要讲的 RoPE 部分 $k_t^R$（64 维），合计 576 个数 / 层 / token。对比 MHA 的 $2\cdot h\cdot d_h = 2\times128\times128 = 32768$ 个数，压缩约 57 倍。

RoPE 为什么必须"解耦"

细心的你会发现图里 RoPE 被单独拉了一条通道，这不是洁癖，是被逼的。

RoPE（旋转位置编码）通过给 $q$、$k$ 乘上与位置相关的旋转矩阵 $R$ 来注入相对位置信息。问题来了：假如让带位置的 $k = R\, W^{UK} c^{KV}$，那么注意力分数里就出现 $q^{\top} R\, W^{UK} c^{KV}$——这个 $R$ 插在两个可学习矩阵中间，且对每个位置都不同：

  • 想预计算吸收矩阵？$R$ 依赖位置，吸收不了；
  • 想只缓存 $c^{KV}$ 等价恢复？$R$ 在中间横着，缓存里没有它的位置。

MLA 的解法是把位置信息分流：内容相似度走 $c$ 通道（不带位置），位置相似度走一条独立的共享 RoPE 通道（$k^R$ 只有 64 维，所有头共用一份）。最终的注意力分数是两段之和：

$$ \text{score}(q_t, k_s) = \big(q_t^{C}\big)^{\top} k_s^{C} \;+\; \big(q_t^{R}\big)^{\top} k_s^{R} $$

这样内容部分可以放心做低秩缓存，位置部分单独缓存一份小小的 $k^R$，两全其美。

矩阵吸收：跑得快的秘密

MLA 还有个进阶技巧，理解它需要一点矩阵转置的耐心。内容通道的分数：

$$ \big(q_i^{C}\big)^{\top} k_i^{C} = \big(W_i^{UQ} c_t^{Q}\big)^{\top} \big(W_i^{UK} c_s^{KV}\big) = \big(c_t^{Q}\big)^{\top} \underbrace{\big(W_i^{UQ}\big)^{\top} W_i^{UK}}_{\text{可预融合}} \, c_s^{KV} $$

中间那个括号与位置无关，完全可以预先算好存起来（"吸收"）。V 侧同理，把 $W^{UV}$ 吸收进输出投影 $W^O$。于是推理时 MLA 甚至不需要显式解压出 K/V，直接拿 $c^{KV}$ 做运算——cache 小、算的还快，等价于一个"超宽 MQA"。（RoPE 那一段因为位置矩阵插在中间，无法吸收——这正是它必须解耦的原因，环环相扣。）

效果与代价

MLA 的账本

收益：DeepSeek-V2 论文报告 KV Cache 减少 93.3%（DeepSeek-V3 约 70 KB/token），且 60 项基准平均分反超 MHA 与 GQA——低秩约束意外起到了正则化效果。V3 的 61 层全部使用 MLA。

代价：实现复杂度上一个台阶（矩阵吸收、RoPE 解耦、专用 kernel）；$W^{UK}, W^{UV}$ 每层参数不小（$d_c \times h \cdot d_h$）；训练与通信模式和主流 GQA 栈不同，生态适配要下功夫。另外和 GQA 比，MLA 的激活值更大（还原多头计算仍要做）。

改变注意力"形状"的变体

MHA → MQA → GQA → MLA 这条线，优化的是 "每个位置存多少 KV"。还有另一条完全不同的战线：干脆改变注意力矩阵的形状——不让每个 token 都看所有 token。这一章过一遍这条线上的代表选手。

SWA：滑窗注意力

Sliding Window Attention（Mistral 7B，2023）简单粗暴：每个 token 只 attend 最近 $w$ 个 token（如 $w=4096$），注意力矩阵从满格变成对角带状。

  • 复杂度：$O(n\cdot w)$，$w$ 固定后随序列长度线性增长；
  • 感受野：单层只能看 $w$，但信息可以逐层接力——第 $L$ 层理论上能"传话"到 $L\cdot w$ 远处；
  • KV Cache：滚动缓冲区，超过 $w$ 的旧格子直接丢弃，cache 被窗口封顶。

纯滑窗会牺牲长程能力，现代用法是混合：绝大多数层用滑窗省开销，穿插少量全局层兜底传远信息。Gemma-2 / Gemma-3 采用"5 层滑窗 + 1 层全局"的节奏；Mistral 系列也用滑窗 + 滚动 cache。这是个"精度换速度"的务实选项，尤其适合局部性强的任务（代码、对话续写）。

Sparse Attention：Longformer / BigBird 一族

更早的长文本探索（2020 前后）把注意力矩阵拆成三种成分的稀疏组合：

  • 全局 token：少数关键位置（如 [CLS]）可以看所有人，也被所有人看；
  • 滑窗：保证局部上下文；
  • 随机 / 膨胀连接：随机拉几条远距离边。理论上随机边能让任意两点的信息路径长度从 $O(n/w)$ 降到 $O(\log n)$ 量级。

思路优雅，但工程实现繁琐（稀疏 kernel 难写高效），逐渐被"滑窗 + 少量全局层"的简洁方案和后面的原生稀疏注意力取代。知道这条脉络即可。

Linear Attention：把 softmax 换掉

另一支奇兵盯上了复杂度的根源——softmax。把 $\text{softmax}(qk)$ 近似为核函数 $\phi(q)\cdot\phi(k)$，于是：

$$ \big(\phi(Q)\phi(K)^{\top}\big)V = \phi(Q)\big(\phi(K)^{\top}V\big) $$

换个括号位置，先算 $\phi(K)^{\top}V$（$d\times d$ 的小矩阵，与 $n$ 无关），复杂度从 $O(n^2)$ 降到 $O(n\cdot d^2)$。Performer、Linear Transformer 是代表。可惜近似 softmax 的质量损失在实际任务中往往得不偿失，主流 LLM 没有采用；不过它的思想活在 RWKV、Mamba 这些线性 RNN 化的架构里——那是另一个故事了。

前沿：原生稀疏注意力（NSA / MoBA）

2025 年的长上下文新解法：与其推理时用启发式规则裁剪注意力，不如训练时就让模型学会"看哪里"。

  • NSA（Native Sparse Attention，DeepSeek，2025）：三分支并行——压缩分支（对 KV 块做粗粒度汇总，先快速定位）、选择分支（门控挑选 top 相关的 KV 块精算）、滑窗分支（保底局部），可学习门控聚合三者。块级稀疏对 GPU 友好，训练推理行为一致。
  • MoBA（Moonshot，2025）：把 MoE 的路由思想搬到注意力上——每个 query 像"专家选择"一样路由到相关的 KV 块。

这条线的野心是让长上下文的成本从 $O(n^2)$ 里真正跳出来，同时由模型自己决定省哪些计算。DeepSeek-V3.1 已经把 NSA 用上生产，值得持续关注。

KV Cache：推理的阿喀琉斯之踵

推理的两个阶段：prefill 与 decode

LLM 推理（自回归生成）实际分两段，瓶颈完全不同：

  • Prefill（预填充）：把整个 prompt 一次性并行喂进去，算出所有位置的 KV 并入缓存。这一步是规整的大矩阵乘（GEMM），算力瓶颈（compute-bound），GPU 利用率高。
  • Decode（解码）：逐个 token 生成。每步只处理 1 个新 token：算它的 $q$，与缓存里全部历史 K/V 做注意力，再把它的 K/V 追加进缓存。这一步是小矩阵乘向量（GEMV），带宽瓶颈（memory-bound）——每生成 1 个 token，都要把整份 KV Cache 从显存搬一遍。

KV Cache 到底多大

一行公式走天下（MHA/GQA/MQA 通用）：

$$ \text{KV Cache 字节} = \underbrace{2}_{K\,\&\,V}\times \underbrace{L}_{\text{层数}}\times \underbrace{n_{kv}}_{\text{KV 头数}}\times \underbrace{d_h}_{\text{头维}}\times \underbrace{b}_{\text{每元素字节}}\times \underbrace{n_{\text{ctx}}}_{\text{token 数}}\times \text{batch} $$

代入几个真实模型（bf16，$b=2$）：

模型Ln_kv × d_h每 token8K 上下文128K 上下文
Llama-3-8B（GQA）328 × 128128 KB1 GB16 GB
Llama-3-70B（GQA）808 × 128320 KB2.5 GB40 GB
DeepSeek-V3（MLA）61576（压缩向量）~70 KB0.55 GB~8.8 GB
假想 70B MHA8064 × 1282.6 MB21 GB335 GB

注意最后一行：如果 70B 用纯 MHA，128K 上下文的 cache 比一台 8×A100 服务器的总显存还大。这就是为什么"现代开源旗舰几乎全员 GQA/MLA"。

三大痛点

  1. 显存容量：cache 和权重抢同一块显存。cache 一胖，batch 就得缩，吞吐崩。
  2. 访存带宽：decode 每步全量读 cache。延迟下限 ≈ cache 字节 ÷ 显存带宽——例如 335 GB 的 cache 在 2 TB/s 的卡上光读取就要 0.17 秒/token。
  3. 分配碎片：传统推理框架按"最大可能长度"为每条请求预留一整块连续显存。实际对话往往用不到最大长度，vLLM 论文测得这种做法浪费 60%–80% 的 KV 显存。

下一章对症下药：少存（结构）、巧存（分页）、存小（量化）、不重算（前缀复用）。

KV Cache 的省钱大法

从源头少存：GQA / MLA

第 4、5 章讲的就是这个：GQA 把份数除以 4~8，MLA 直接把维度压缩 50 倍以上。它们作用于"每个 token 的 cache 尺寸"，是所有优化的地基——先少存，再谈怎么存。

PagedAttention：像操作系统一样管显存

痛点 3（碎片）的经典解法，来自 vLLM（2023）。思路直接抄作业操作系统：

  • 把逻辑上连续的 KV Cache 切成固定大小的块（block，如 16 个 token 一块）；
  • 物理显存里维护一个全局块池，按需分配，逻辑相邻的块物理上不必相邻；
  • 每条请求配一张块表（block table）：逻辑块号 → 物理块号，注意力计算时按表取块拼接。

收益立竿见影：

  • 碎片 < 4%（对比传统预留式分配的 60–80% 浪费）；
  • 同显存能塞下更大的 batch 与上下文，吞吐倍增（vLLM 论文：较 HF Transformers 最高 24×，较 TGI 约 3.5×）；
  • 前缀共享：多条请求共享同一 system prompt 时，物理块可以引用同一份（copy-on-write），省显存也省 prefill 计算。

存小一点：KV Cache 量化

K/V 的数值分布其实相当"好脾气"，量化空间很大：

  • FP8 / INT8：容量、带宽直接减半，精度损失几乎不可测，主流推理引擎（TensorRT-LLM、vLLM 等）均已支持；
  • 4-bit 及以下（如 KIVI）：K 按通道、V 按 token 的混合量化粒度，配合少量校准，轻微掉点换 4× 以上的容量；
  • 带宽同步下降 → decode 延迟也跟着降，一举两得。

别存多余 & 别重算

  • 滑窗封顶：SWA 模型的 cache 被窗口 $w$ 封顶，长会话不再线性膨胀（回顾 6.1）；
  • 前缀缓存（prefix caching）：把已算好的 KV 块按前缀哈希存下来，命中相同前缀（system prompt、few-shot 模板）的请求直接跳过 prefill。vLLM 的 automatic prefix caching、SGLang 的 RadixAttention 都是这个思路；
  • 卸载与重算：极端长会话下，可以把冷门层的 KV 换出到 CPU/SSD（分层存储），或干脆丢掉一部分靠重算补回——用计算换显存，属于压箱底手段。

让 Attention 算得更快

先分清：到底卡在算力还是带宽

GPU 性能有两个天花板：算力（FLOPS）和显存带宽（bytes/s）。一个算子到底受限于谁，看它的算术强度（每读写 1 字节做多少次浮点运算）：

  • Prefill / 训练的 attention：一次处理几百上千个 token，是大 GEMM，算术强度高 → compute-bound，优化方向是让 tensor core 吃满、减少冗余读写；
  • Decode 的 attention：每步 1 个 token 对全部历史，是 GEMV，算术强度极低 → memory-bound，优化方向是少读数据（GQA/MLA/量化）+ 提高带宽利用率（大 batch）。

FlashAttention 主要治前者（以及训练），GQA/量化治后者，两者正交、可叠加。

FlashAttention：不近似，只是会搬家

标准实现的毛病在 IO。算 $\text{softmax}(QK^\top)V$ 时，朴素流程要把中间结果 $S = QK^\top$（$n\times n$）写回显存、读回来做 softmax 得到 $P$（又是 $n\times n$）、再写回、再读回来乘 $V$。以 A100 为例：HBM 带宽约 1.5 TB/s，而 SM 的片上 SRAM 高达约 19 TB/s——慢的不是算，是搬。

FlashAttention（Tri Dao, 2022）三板斧：

  1. Kernel 融合：整个 attention 融成一个 CUDA kernel，中间结果不落盘；
  2. Tiling（分块）：Q 按行分块、K/V 按列分块，小块装进 SRAM 里算，算完即弃；
  3. Online softmax：softmax 依赖整行的 max 与 sum，分块后怎么办？——维护运行中的 max（$m$）与 sum（$l$），每来一块就"修正"旧结果。

Online softmax 是精髓，值得亲手推一遍：处理第 $j$ 个 KV 块时，

$$ m^{(j)} = \max\big(m^{(j-1)},\ \text{rowmax}(S_j)\big),\qquad \ell^{(j)} = e^{m^{(j-1)}-m^{(j)}}\,\ell^{(j-1)} + \text{rowsum}\big(e^{S_j - m^{(j)}}\big) $$ $$ O^{(j)} = e^{m^{(j-1)}-m^{(j)}}\,O^{(j-1)} + e^{S_j - m^{(j)}} V_j,\qquad O_{\text{final}} = O^{(\text{last})}/\ell^{(\text{last})} $$

翻译成人话：新块可能刷新最大值，于是旧累积结果统一乘上修正系数 $e^{m_{old}-m_{new}}$ 缩一下，再把新块的贡献加上——和"把所有数都拿到手里再归一化"在数学上完全等价。

# FlashAttention 核心循环（每个 Q 块独立执行，可并行）
for Q_i in Q 的行块:
    O_i = 0;  m = -inf;  l = 0            # 行级 running max / sum
    for (K_j, V_j) in KV 的列块:      # 块从 HBM 流式载入 SRAM
        S_ij = Q_i @ K_j.T / sqrt(d)      # 只存在于 SRAM，从不写回 HBM
        m_new = max(m, rowmax(S_ij))
        P = exp(S_ij - m_new)             # 数值安全
        alpha = exp(m - m_new)            # 旧结果的修正系数
        l = alpha * l + rowsum(P)
        O_i = alpha * O_i + P @ V_j       # 增量更新输出
        m = m_new
    O_i = O_i / l                          # 最后统一归一化
FlashAttention 的三重身份

① 精确算法：数学上与朴素实现等价（只差浮点舍入顺序），不是近似；② 显存优化：不再物化 $n\times n$ 矩阵，激活显存从 $O(n^2)$ 降到 $O(n)$，长上下文训练因此可行；③ IO 优化：HBM 访问从 $O(n^2 + nd)$ 降到 $O(n^2 d^2 / M)$（$M$ 为 SRAM 大小），训练/长序列 prefill 提速数倍。

FlashAttention-2 / 3：接着卷

  • FA2（2023）：重新划分并行维度（长序列下沿序列维并行）、更均衡的 warp 分工、砍掉非 matmul 的冗余运算——同一硬件上比 FA1 再快约 2×；
  • FA3（2024）：为 Hopper（H100）定制——TMA 异步搬运、WGMMA 异步矩阵乘、两组 warp 乒乓（ping-pong）调度让数学与数据搬运永不互相等待，还支持 FP8。对 FA2 再提速 1.5–2×。

顺带一提，因果掩码在分块视角下有优雅的处理：若 KV 块整体在 Q 块的"过去"，无需掩码直接算；整体在"未来"，整块跳过；只有跨对角线的块才逐元素掩码——这也是分块实现天然吃到的红利。

Ring Attention：上下文长度上不封顶

想让序列长到一台设备装不下？Ring Attention（2023）的思路：把序列沿设备环切开，每台设备只持有自己那段的 Q/K/V；K/V 块沿环形拓扑逐站轮转，通信与计算重叠——上一块数据在算的时候，下一块已经在路上。转完一圈，每台设备都见过了所有 K/V，注意力算完，上下文长度上限 ≈ 单机长度 × 设备数。百万级 token 的训练由此成为可能。

系统层组合拳

  • Continuous batching（vLLM / Orca）：调度粒度从"整个请求"细化到"每次迭代"，谁生成完了立刻让位给排队的新请求，消灭 GPU 空转；
  • 投机解码（speculative decoding）：小模型先草拟 k 个 token，大模型一次 forward 并行验证，接受的直接采纳——不改变输出分布的"合法加速"，与 attention 优化正交；
  • Prefix caching：命中即跳过 prefill（回顾 8.4）。

现代推理引擎（vLLM、SGLang、TensorRT-LLM）本质上是把这些招式全叠起来：结构上 GQA/MLA，显存上分页 + 量化，kernel 上 FlashAttention，调度上 continuous batching——这正是"Attention 生态"的全貌。

把一切串起来

一句话心智模型

注意力的一切麻烦都源自 $n^2$ 的两难：算得动，存不起、搬不动。于是有两条主线——

存得少：MHA → MQA → GQA → MLA（压 KV 的份数与维度），SWA / NSA（干脆少看）；

搬得快：FlashAttention（不落盘）、PagedAttention（不浪费）、量化（变小）、continuous batching / Ring Attention（多卡多请求协同）。

两条线正交组合，就是今天你用的每一个推理引擎。

常见疑问快问快答

为什么只缓存 K/V，不缓存 Q？

因为复用价值完全不同：每个 token 的 $q$ 只在"生成它"的那一步被用到，是即算即弃的一次性消费品；而 $k, v$ 会被之后所有步骤反复读取。缓存的定义就是"留着以后再用"，Q 没有以后。

FlashAttention 是近似算法吗？会改变模型输出吗？

不是近似。它只改变计算的执行顺序与数据搬运路径（分块 + online softmax 的增量修正数学上严格等价于先算完再 softmax），输出与朴素实现只差浮点运算顺序带来的舍入误差。训练、推理都能放心用。

softmax 前为什么要减去最大值？

纯为了数值稳定：$e^x$ 溢出极快，长序列下分数动辄上百，直接 exp 会得到 inf。减去行最大值后最大的指数项恰为 $e^0=1$，数学上完全等价（分子分母同乘常数），数值上岁月静好。FlashAttention 的 online softmax 就是围绕"运行中的最大值"做增量修正。

Decode 阶段为什么说它是 memory-bound？

每生成一个 token，都要把整份 KV Cache 从显存读一遍，却只产出 1 个 token 的计算量——算术强度（FLOPs/字节）极低，GPU 的计算单元大量空转，时间几乎全花在搬数据上。所以 decode 的延迟下限 ≈ cache 大小 ÷ 显存带宽，优化方向是让 cache 变小（GQA/MLA/量化）或让带宽不空转（大 batch）。

MLA 和 LoRA 是一回事吗？

只是共享"低秩"这个数学工具。LoRA 用低秩矩阵微调大模型（省的是训练参数）；MLA 用低秩压缩缓存KV（省的是推理显存与带宽）。一个面向训练效率，一个面向推理效率，理论上还能组合使用。

GQA 的分组数有什么讲究？

工程上几乎总取 2 的幂（如 64Q:8KV），reshape 与 kernel 都友好；组比（每多少个 Q 头配一套 KV）常见 4:1 到 16:1。经验规律：模型越大，可承受的共享程度越高（70B 用 8:1 几乎无损，7B 用 4:1 更稳妥）。

把 MHA 模型改造成 GQA，必须从头重训吗？

不必。GQA 论文的 uptraining 方案：把同组 Q 头的 KV 投影权重取平均作为共享投影的初始化，再用约 8% 的原训练量继续预训练即可，质量几乎追平原生 MHA。Llama-2-70B 就是这么从 Llama-2 架构演进过来的（论文中对比了 MHA 原型）。

KV Cache 量化会掉点吗？掉多少？

FP8/INT8 基本无感（困惑度扰动在小数点后）；4-bit 有轻微掉点，需要合理的量化粒度（如 KIVI 的 K 按通道、V 按 token）与校准；2-bit 属于极限操作，长上下文任务上退化明显。工程上 FP8 KV 已经是"免费午餐"级别的标配。

PagedAttention 的块表查找会不会拖慢注意力？

几乎不会。块表是常驻显存的小数组，间接寻址开销与注意力本体的大规模读写相比可忽略；换来的是碎片从 60–80% 降到 4% 以内，同样的显存能服务多得多的请求，吞吐收益远大于寻址成本。

多头数量怎么选？头越多越好吗？

不是。总维度 $d_{model}$ 固定时，头数 × 每头维度是零和的：头太多，每头维度太低，单个注意力分布的表达力受限；头太少又浪费多视角。经验甜点位是每头 64–128 维（如 4096 维配 32 头或 64 头），并取 2 的幂以方便并行。

batch 越大吞吐越高吗？

在 decode 阶段，加大 batch 能把带宽利用率摊高（cache 读取被多条请求复用同一趟权重读取），吞吐近乎线性上升——直到 KV Cache 撑爆显存或带宽打满为止。这就是 PagedAttention + GQA 价值连城的原因：它们直接抬高了这条曲线的天花板。
